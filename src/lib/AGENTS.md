- Compound adds harvested tokens to the same verified position: no swap/extra SOL wrap, capped by harvest, simulated.
- Live predictions: only BTC/ETH/SOL Up-or-Down rounds (5m/15m/4h) from Polymarket via Jupiter Prediction API, one current round per asset/window, wallet sole signer, simulated before review, executed via /execute; no practice mode; BÓVEDA is never counterparty. 4 h rounds carry no tag and never appear under filter=live, so the server also reads the unfiltered crypto pages and identifies the window by slug (updown-4h), tag or exact round length.
- Server functions that spend the private Helius quota use requirePrivyAuth (Privy JWT via x-boveda-auth header, getter registered by the session bridge) so anonymous callers cannot drain it.
- Cash App withdrawals: USDC→native BTC via SideShift fixed quote (server-only creds), verified shift pair/address before one wallet-signed USDC transfer; app enforces a minimum so fixed BTC network costs stay small; BÓVEDA tiered fee (withdrawFee, FEE_TIERS in fees.ts) deducted from gross and sent in the same signed transaction; bank/exchange USDC withdrawals too.
- Single treasury: affiliate payouts are sent from FEE_WALLET itself (AFFILIATE_PAYOUT_WALLET aliases it; key only in server secret AFFILIATE_PAYOUT_SECRET_KEY, verified to match before signing) so the operator has one wallet; affiliates self-claim by co-signing as fee payer (treasury pre-signs the USDC transfer, affiliate pays network SOL; rows locked pending→paid, released on cancel or after 5 min, recorded only after on-chain verification); the operator treasury dashboard shows balance, affiliate reserve and profit = USDC − pending commissions.
- Up/Down claim fee (PREDICT_CLAIM_BPS of total payout) rides on the wallet-signed JupUSD→USDC conversion after the venue claim (the venue-built claim tx is never modified); affiliates are credited from that signature like any other fee.
- Operator VIP codes (affiliate-vip-admin.tsx) are always single-use, 60–90%, gated server-side by payoutAdmin (verified treasury wallet owner).
- Telegram: channel posts and operator alerts go server-side through the Telegram connector (telegram.server.ts); publishing is gated by payoutAdmin and alerts never block payments.
- Personal Telegram alerts: users link via one-time t.me/bovedamarketbot?start=code (10 min) handled by /api/public/telegram/webhook (secret-token verified); telegram_links is service-role only; userAlert is best-effort and never blocks; each alert passes its kind (alert-kinds.ts) and is skipped when muted (all kinds on by default).
- Suggestions: signed-in users submit via requirePrivyAuth (3/day, 500 chars, suggestions.ts); user_suggestions is service-role only; operator reads/marks in Tesorería gated by payoutAdmin; treasuryAlert notifies best-effort.
- System status (/status) uses public health probes and DefiLlama global metrics via one cached (60s) server function so visitors cannot amplify upstream calls; never private Helius.
- Downtime monitor: managed cron (2 min) hits /api/public/jobs/check-system-status (cron-auth), reuses probeServices; status-monitor.ts decides operator alert at first failure, public channel only after 3 min down plus recovery post; state in service-role-only system_service_status.
- Sube/Baja result alerts: the bell derives won-unclaimed/lost rounds from the shared positions query; Telegram alerts go through notifyPredictResults, which re-reads outcomes server-side and dedups once per account+position in service-role-only predict_result_alerts ; the app also stores the wallet on telegram_links so the 2-min status cron sends the same deduped alerts while the app is closed.
- Liquidation leftovers: after a confirmed non-migration exit, sweep-leftovers.ts converts wallet JupUSD and validated non-SOL vault tokens to USDC in separate free wallet-signed swaps (dust under 0.01 USDC skipped); the atomic exit itself stays delta-only and native SOL reserve is never swept.
- Network-reserve refill (gas-refill.ts): when SOL < low threshold, the treasury (FEE_WALLET) pre-signs as fee payer a tx sending SOL up to SOL_RESERVE_LAMPORTS in exchange for a USDC transfer (market + margin) in the same tx, simulated, user co-signs; works at 0 SOL, treasury never loses net.
- Trading gate: client signAndSend/signOnly and every server function that builds/simulates/executes a user operation (assertTradingWallet in trade-guard.server.ts, Privy REST linked_accounts with PRIVY_APP_SECRET, fail-closed) allow the caller's own linked wallets; external wallets are view-only only while the operator switch (wallet-policy.server.ts, payoutAdmin-gated, row in system_service_status) is on, and FEE_WALLET never trades; treasury payouts use signAndSendAdmin only.
- When adding avatar IDs to AVATAR_IDS, widen the account_profiles.profile_avatar CHECK in the same change; otherwise profile saves fail (guarded by avatar-constraint.test.ts).
- Browser polyfills are kept by an explicit exported call plus the package.json "sideEffects" list; never rely on a bare side-effect import, which the production build tree-shakes.
- Operator mailbox (mailbox-admin.tsx): reads/sends via the Gmail connector server-side only, every call gated by payoutAdmin; sending only from Gmail send-as aliases (domain addresses forwarded to that Gmail), header values stripped of line breaks.
- Privy custom API domain fallback (privy-api-fallback.ts): app-config custom_api_url is dropped when that host is unreachable so login falls back to auth.privy.io; installed by explicit call in privy-access.
- Google Analytics 4: measurement ID stays in server secret GOOGLE_ANALYTICS_MEASUREMENT_ID, returned by getAnalyticsId and loaded client-side by GoogleAnalytics in __root (SPA page_view on route change).
- Vault move suggestions (migrate banner + Telegram APR-gap post) only run while the operator switch (migrate-policy.server.ts, payoutAdmin-gated, row in system_service_status) is on; default off because moves cost swap slippage.
- Sube/Baja refunds: a signed buy only creates an order; the app polls the venue order status (orderPubkey from the build) before saying "activa", and failed fills come from the public venue history (order_failed, predict-refunds.ts, 24 h). Bell, Mi Billetera "Reembolso listo" and Telegram (client + 2-min cron, deduped as order:<pubkey> in predict_result_alerts) share that source; CloseOrder alone is not a refund because it also follows normal fills.
- Treasury SOL monitor: 2-min status cron alerts the operator once below TREASURY_SOL_LOW and on recovery (treasury-reserve.ts, row treasury_sol in system_service_status); /admin header shows the same banner.
